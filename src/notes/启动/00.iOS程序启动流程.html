iOS 程序启动流程

整体流程

阶段 步骤
1. 系统启动阶段 系统启动 → 内核加载 App 可执行文件 → 创建进程
2. 动态链接阶段 dyld 动态链接器启动 → 检查 Launch Closure（iOS 13+，如存在可跳过符号解析） → 加载动态库 → Rebase & Bind
3. Runtime 初始化阶段 libSystem.dylib 初始化 → 调用 _objc_init → 向 dyld 注册 map_images/load_images/unmap_image 回调 → map_images 读取 Mach-O 的 __DATA 段，注册类信息到内存类表
4. 初始化阶段 调用 +load 方法（通过 load_images 回调） → 调用 C++ 静态构造函数
5. main 函数阶段 调用 main 函数 → UIApplicationMain
6. 应用启动阶段 创建 UIApplication 实例 → 创建 AppDelegate 实例 → 设置 UIApplication 的 delegate → 启动主 RunLoop → 调用 didFinishLaunching → 读取 Main Bundle 资源（Info.plist、LaunchScreen.storyboard 等）
7. 界面显示阶段 创建 Window → 设置 RootViewController → 视图控制器加载 → 视图布局 Layout → 视图绘制 Display → 提交到 Render Server → GPU 渲染 → 显示到屏幕

关键细节说明

Launch Closure（启动闭包）

时间点：dyld 启动后，加载动态库之前

作用：dyld 3/4（iOS 13+）引入的优化机制。如果存在预构建的启动闭包，dyld 可以直接使用缓存的符号解析结果，跳过复杂的 Rebase & Bind 过程，大幅缩短启动时间。

缓存机制：启动闭包使用 SHA256 哈希作为文件名，基于主可执行文件的 inode、修改时间和系统启动时间生成。

ObjC Runtime 注册

时间点：在 +load 方法调用之前

流程：

  1. libSystem.dylib 初始化时调用 _objc_init
  2. _objc_init 向 dyld 注册三个回调函数：
    • map_images：镜像映射时调用，读取 Mach-O 的 __DATA 段，创建类存储表并初始化类信息
    • load_images：准备并执行 +load 方法
    • unmap_image：镜像卸载时调用
  3. dyld 在加载镜像时调用 map_images，从 Mach-O 的 __DATA 段读取类信息，映射到内存中的类表
  4. 没有这一步，后续的 +load 和消息发送都无法进行

Main Bundle 资源读取

时间点：在 didFinishLaunching 之后，界面显示之前

内容：读取 Info.plist、加载 LaunchScreen.storyboard 等 Main Bundle 中的资源文件。这些 I/O 操作是 First Frame（首帧）准备的一部分。

注：Info.plist 的部分信息可能在更早阶段就被读取（dyld 加载时需要），但完整的资源加载通常发生在应用启动阶段。
