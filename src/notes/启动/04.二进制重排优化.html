二进制重排优化（Binary Reordering）

1. 概述

二进制重排是一种启动优化技术，通过调整二进制文件中函数/方法的排列顺序，把启动时实际用到的「热代码」放到文件前面，减少缺页中断（page fault），从而加快启动速度。

1.1 核心原理

问题：代码分散在文件各处
    ↓
启动时需要多次读磁盘，产生很多缺页中断
    ↓
很慢

解决：重排代码顺序
    ↓
启动代码集中在前面几页，按顺序连续读几页
    ↓
快很多

1.2 优化哪个阶段

二进制重排主要优化的是加载阶段的速度：

  1. 系统启动阶段：内核加载 App 可执行文件时（mmap 映射到虚拟地址空间）
  2. 动态链接阶段：dyld 加载动态库时（也是 mmap 映射）

为什么是加载阶段：iOS 使用虚拟内存，代码按页（16KB）加载。启动时如果需要的代码分散在文件各处，系统要多次从磁盘读不同的页，产生很多缺页中断（page fault），很慢。重排后，启动代码集中在前面几页，按顺序连续读几页就够了，大幅减少缺页中断。

1.3 和动态链接阶段的关系

方面 二进制重排 动态链接阶段
发生时机 编译/链接时（生成二进制时） 运行时（App 启动时）
优化目标 减少缺页中断，让启动时需要的代码更集中 修正地址、绑定符号，让代码能正确运行
影响阶段 主要影响加载阶段（mmap 映射、按需加载页） 发生在加载之后，做 Rebase & Bind
关系 重排让启动代码更集中，加载更快 → 动态链接阶段能更快访问到需要处理的代码 → 整体启动更快 两者配合：重排优化加载，动态链接确保代码正确

简单理解：二进制重排把启动时需要的代码「打包」到文件前面，启动时按顺序读，减少跳来跳去读磁盘。动态链接阶段是代码已经加载到内存后，修正地址、绑定符号，让代码能跑起来。两者配合优化启动速度。

2. 实操步骤

2.1 方法一：使用 Clang Sanitizer 收集数据（推荐）

步骤1：配置编译选项（启用 Sanitizer Coverage）
    ↓
步骤2：添加收集代码（在启动入口）
    ↓
步骤3：运行 App（完成启动流程）
    ↓
步骤4：导出数据（生成 Order File）
    ↓
步骤5：在 Xcode 配置（Order File 路径）
    ↓
步骤6：重新编译（链接器按顺序排列）

步骤 1：收集启动时的函数调用数据

在 Xcode 中配置编译选项，启用 Sanitizer Coverage：

  1. 选择 Target → Build Settings
  2. 搜索 Other C Flags 或 Other C++ Flags
  3. 添加：-fsanitize-coverage=func,trace-pc-guard
  4. 搜索 Other Swift Flags
  5. 添加：-sanitize-coverage=func 和 -sanitize=undefined

步骤 2：在代码中收集调用信息

在 App 启动入口（如 main 函数或 AppDelegate 的 didFinishLaunching）添加收集代码：

// AppDelegate.swift
import Foundation

#if DEBUG
@_silgen_name("__sanitizer_cov_trace_pc_guard_init")
func __sanitizer_cov_trace_pc_guard_init(_ start: UnsafeMutablePointer<UInt32>, _ stop: UnsafeMutablePointer<UInt32>) {
    // 初始化
}

@_silgen_name("__sanitizer_cov_trace_pc_guard")
func __sanitizer_cov_trace_pc_guard(_ guard: UnsafeMutablePointer<UInt32>) {
    // 记录函数调用
    let pc = __builtin_return_address(0)
    // 写入文件或内存，记录调用顺序
}
#endif

或者使用第三方工具如 AppOrderFiles 自动收集。

步骤 3：运行 App，收集数据

  1. 运行 App，完成启动流程（到首屏显示）
  2. 收集到的数据会记录在文件或内存中
  3. 导出数据文件（通常是文本格式，每行一个函数名）

步骤 4：生成 Order File

把收集到的函数名整理成 order file（.order 文件），格式：

-[ViewController viewDidLoad]
-[AppDelegate application:didFinishLaunchingWithOptions:]
_main
objc_msgSend
...

按调用顺序或频率排序，最常用的放前面。

步骤 5：在 Xcode 中配置 Order File

  1. 选择 Target → Build Settings
  2. 搜索 Order File
  3. 填入 order file 的路径（相对路径或绝对路径），例如：$(SRCROOT)/order_file.order

步骤 6：重新编译

重新编译 App，链接器会按照 order file 的顺序排列函数/方法。

2.2 方法二：手动编写 Order File（简单但不够准确）

步骤 1：手动编写 Order File

根据代码分析，手动列出启动时可能调用的函数：

_main
-[AppDelegate application:didFinishLaunchingWithOptions:]
-[ViewController viewDidLoad]
-[ViewController viewWillAppear:]
...

步骤 2：在 Xcode 中配置

同方法一的步骤 5。

步骤 3：验证和优化

  • 运行 App，用 Instruments 的 System Trace 或 Time Profiler 验证
  • 观察缺页中断（Page Fault）数量是否减少
  • 根据实际调用情况调整 order file

3. 验证效果

3.1 使用 Instruments 验证

  1. 打开 Instruments → System Trace
  2. 运行 App，记录启动过程
  3. 查看 Page Faults 数量：重排后应该明显减少（通常减少 20-50%）
  4. 对比启动时间：通常能缩短 100-500ms

3.2 实际效果

  • 通常能减少 20-50% 的缺页中断
  • 启动时间可能缩短 100-500ms（取决于 App 大小和启动路径复杂度）

4. 注意事项

  • Order file 只影响主可执行文件的排列，不影响动态库
  • 如果 App 更新了启动流程，需要重新收集数据并更新 order file
  • Debug 和 Release 配置可以分别配置不同的 order file
  • Order file 中的函数名必须完全匹配，包括 Objective-C 的方法名格式（-[ClassName methodName:]）
